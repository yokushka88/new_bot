# Платформа магазинів у Telegram

Один бот і один сервер на будь-яку кількість магазинів.

- **Покупці** відкривають магазин як Telegram Mini App (кнопка в боті) або як сайт,
  який можна встановити на телефон (PWA) — без App Store і Google Play.
- **Власники** керують магазином прямо в боті: додають товари (можна просто переслати
  пост зі свого каналу — бот сам візьме фото, назву, ціну, розміри й кольори), змінюють ціни
  й наявність, отримують замовлення в Telegram.
- **Адміністратор платформи** (ви) створює магазини й надсилає власникам запрошення.

## Встановлення на власний сервер (Hetzner тощо)

Сервер Ubuntu 22.04/24.04 (напр. Hetzner CX22, ~€4/міс) і адреса, що вказує на його IP
(напр. безкоштовна `myshops.duckdns.org`). У консолі сервера від root:
```bash
curl -fsSL https://raw.githubusercontent.com/yokushka88/new_bot/main/deploy/install.sh -o install.sh && bash install.sh
```
Скрипт запитає адресу, токен бота й ваш Telegram ID, а далі сам встановить Node.js 22, Caddy (HTTPS),
автозапуск, фаєрвол і оновлення безпеки. Оновити платформу з GitHub: `shop-update`.
Журнал: `journalctl -u shop -f`. База й фото: `/var/lib/shop` (увімкніть Backups у Hetzner).

## Налаштування Railway (один раз)

1. **New Project → Deploy from GitHub repo** → цей репозиторій.
2. **Диск для бази й фото (обов'язково!)**
   на полотні проєкту: **+ Create → Volume** → підключіть до сервісу, **Mount path: `/data`**.
   Без Volume товари й фото зникатимуть після кожного оновлення.
3. **Variables:**
   - `BOT_TOKEN` — токен бота з @BotFather;
   - `ADMIN_IDS` — ваш Telegram ID (кілька — через кому);
   - `DATA_DIR` = `/data`;
   - `TOKEN_SECRET` — довгий випадковий рядок для шифрування токенів ботів клієнтів (рекомендовано).
4. **Settings → Networking → Generate Domain**, порт `8080`.
5. **Deployments → ⋮ → Redeploy**. У логах має бути:
   `Бот: @… запущено, сайт https://…`

## Як працює

**Новий магазин** — напишіть боту:
```
/newshop snake Casual snake drop
```
`snake` — коротке ім'я латиницею (буде в посиланнях). Бот видасть:
- **запрошення для власника** (одноразове) — надішліть йому;
- **посилання для покупців** `t.me/<бот>?start=s_snake` — для каналу;
- **сайт** `https://<домен>/s/snake` — його можна встановити на телефон.

Інші команди адміністратора: `/shops`, `/invite slug`, `/manage slug` (наповнити магазин самому),
`/pause slug`, `/resume slug`.

**Власник** відкриває запрошення → отримує меню:
- ➕ **Додати товар** — фото → назва → бренд → ціна → категорія → розміри → кольори → опис;
  або **переслати пост з каналу** з фото — більшість полів заповниться саме;
- 📦 **Мої товари** — наявність, ціна, знижка, розміри в наявності, назва, опис, видалення;
- 🔗 **Посилання** — для каналу й для встановлення на телефон;
- ⚙️ **Налаштування** — назва, менеджер, доставка, відгуки, банер.

**Свій бот (за бажанням клієнта).** «⚙️ Налаштування» → «🤖 Підключити свій бот» → власник
надсилає токен бота з @BotFather. Повідомлення з токеном бот одразу видаляє, токен зберігається
в базі зашифрованим (AES-256-GCM, ключ — `TOKEN_SECRET` або похідний від `BOT_TOKEN`).
Покупці заходять через бот клієнта з його назвою; керування й замовлення лишаються в боті платформи.
Клієнт може відключити бота в налаштуваннях або відкликати токен у @BotFather — тоді бот
автоматично відключається, а власник отримує попередження.

> Якщо змінити `BOT_TOKEN` платформи без `TOKEN_SECRET`, збережені токени клієнтів перестануть
> розшифровуватися — тоді клієнтам треба підключити ботів заново. Щоб цього уникнути, задайте
> `TOKEN_SECRET` (будь-який довгий випадковий рядок) одразу при першому запуску.

**Замовлення** приходять власнику в Telegram від бота. Ціни й наявність сервер перевіряє за
своєю базою; дані покупця з Telegram перевіряються за підписом (initData).

## Встановлення на телефон (PWA)

- Android: браузер сам пропонує «Встановити», у магазині також є кнопка.
- iPhone: «Поділитися» → «На екран Додому» (магазин показує підказку).

## Розробка

```bash
npm install
npm run build && npm start   # сервер на http://localhost:3000, сторінки /s/<slug>
npm run test:e2e             # 38 наскрізних перевірок з імітацією Telegram
```

Структура: `server.mjs` — HTTP-сервер; `server/` — база (SQLite у `DATA_DIR`), бот, каталог,
перевірка замовлень; `src/` — застосунок магазину (React); `public/` — іконки й service worker.

## Безпека

- Токен бота лише на сервері; фото завантажуються сервером і віддаються з випадковими іменами.
- Ціни й наявність у замовленні перераховуються на сервері; обмеження частоти замовлень.
- initData з Telegram перевіряється за HMAC-підписом; підроблені дані відхиляються.
- Керувати товарами може лише власник магазину або адміністратор.
- Заголовки безпеки (CSP, HSTS, nosniff), захист від виходу за межі тек.
